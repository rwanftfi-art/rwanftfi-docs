RWANFTFI utiliza una arquitectura Diamond [EIP-2535](https://eips.ethereum.org/EIPS/eip-2535) con siete facets funcionales, contratos NFT y de reserva independientes, mecanismos de actualizabilidad definidos, permisos basados en roles y múltiples tipos de saldo interno.

## Facets del Diamond

| Facet | Función |
|---|---|
| AdminFacet | Roles, parámetros, transferencias aprobadas y minteo de NFT especiales. |
| MarketingFacet | Registro, compras de NFT y cálculos de recompensas de socios. |
| FarmingFacet | Minería de NFTM y Farming de DA. |
| PaymentFacet | Depósitos, retiradas, vouchers y transferencias de saldo. |
| TreeFacet | Colocación y profundidad de la red de socios. |
| ResolverFacet | Valores expirados, procesamiento de vouchers y resolución de Frozen Balance. |
| ViewFacet | Consultas de solo lectura de usuario, saldo y red. |

## Contratos NFT

- Los NFT Regulares usan IDs de token impares.
- Los NFT de Regalo usan IDs de token pares.
- Los NFT Ambassador usan un contrato y una configuración independientes.

## Matriz de Actualizabilidad

| Componente | Modelo |
|---|---|
| Contrato Diamond | Actualizable mediante cortes de facets. |
| TokenReserve / DA | Actualizable mediante el mecanismo de proxy documentado. |
| Contratos NFT | Documentados como no actualizables. |
| GovToken | Documentado como no actualizable, con suministro fijo. |
| AdminContract | Documentado como no actualizable. |

## Gestión de Roles

| Rol | Autoridad Documentada |
|---|---|
| `ADMIN_ROLE` | Otorga y revoca roles; modifica los parámetros del protocolo permitidos. |
| `SERVICE_ROLE` | Ejecuta las operaciones automatizadas y cross-chain documentadas. |
| `SIGNER_ROLE` | Verifica firmas autorizadas para acciones especificadas. |
| `MINTER_ROLE` | Acuña el token o tipo de NFT asignado a ese rol. |

## Esquema de Saldos

| Saldo | Propósito |
|---|---|
| Saldo Regular | Retiradas, compras y vouchers elegibles. |
| Saldo Acumulativo | Saldo interno restringido utilizado bajo las reglas documentadas de compra, transferencia, comisión y redistribución. |
| Límite de Recompensas del Protocolo | Elegibilidad de recompensa restante para el ciclo de NFT activo; término on-chain: *Income Limit*. |
| Saldo de Reserva de Tokens | Saldo designado del pool de liquidez que respalda la mecánica del DA. |
| Saldo Dev | Asignaciones operativas y del protocolo. |
| Saldo de Impacto de Precio | Reserva utilizada por las funciones documentadas de impacto de precio. |

## Prioridad de Pagos

<Steps>
  <Step title="Voucher válido seleccionado">
    Si el usuario aplica explícitamente un voucher válido al finalizar la compra, su valor se consume primero.
  </Step>
  <Step title="Saldo Acumulativo">
    Se aplica cuando es elegible y está seleccionado, bajo las reglas de comisión documentadas.
  </Step>
  <Step title="Saldo Regular">
    Cualquier monto restante se deduce del Saldo Regular.
  </Step>
</Steps>

<Note>
  Todas las transacciones en [BNB Smart Chain](https://www.bnbchain.org/en/bnb-smart-chain) requieren las tarifas de gas estándar de la red, pagadas en **BNB**, independientes de los saldos en [USDT](https://tether.to/) utilizados dentro del ecosistema. Los despliegues de contratos y los saldos son públicamente verificables en [BscScan](https://bscscan.com/).
</Note>
