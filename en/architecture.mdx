## Diamond Facets

| Facet | Function |
|---|---|
| AdminFacet | Wallet changes and account restrictions, special NFT minting, and automated service operations. |
| ParametersFacet | Protocol parameters, NFT settings, Gift NFT types, function switches, farming periods, and fee ranges. |
| MarketingFacet | Registration, NFT purchases, and partner-reward calculations. |
| FarmingFacet | NFTM Mining and DA Farming. |
| PaymentFacet | Deposits, withdrawals, vouchers, and balance transfers. |
| TreeFacet | Partner-network placement and depth. |
| ResolverFacet | Expired values, voucher processing, and Frozen Balance resolution. |
| ViewFacet | Read-only user, balance, and network queries. |

The Diamond also includes the standard EIP-2535 facets: DiamondCutFacet for upgrades, DiamondLoupeFacet for introspection, and OwnershipFacet.

## NFT Contracts

- Regular NFTs use odd token IDs.
- Gift NFTs use even token IDs.
- Ambassador NFTs use a separate contract and configuration.

## Upgradeability Matrix

| Component | Model |
|---|---|
| Diamond Contract | Upgradeable through facet cuts. |
| TokenReserve / DA | Upgradeable through the documented proxy mechanism. |
| NFT Contracts | Documented as non-upgradeable. |
| GovToken | Documented as non-upgradeable with fixed supply. |
| AdminContract | Documented as non-upgradeable. |

## Role Management

| Role | Documented Authority |
|---|---|
| DAO contract | Applies parameter updates within the on-chain ranges, changes NFT settings, enables or disables functions, sets farming periods and fee ranges, approves wallet changes, and restricts or restores accounts. |
| `ADMIN_ROLE` | Grant and revoke roles; mint Gift and Ambassador NFTs and manage Gift NFT types; set the transaction fee within its range. |
| `SERVICE_ROLE` | Execute documented automated and cross-chain service operations. |
| `SIGNER_ROLE` | Verify authorized signatures for specified actions. |
| `MINTER_ROLE` | Mint the token or NFT type assigned to that role. |
| Diamond owner | Facet upgrades through `diamondCut` and ownership transfer. |

The function-level list for every role is in the centralization section of the [CertiK report](/en/security).

## Balance Schema

| Balance | Purpose |
|---|---|
| Regular Balance | Eligible withdrawals, purchases, and vouchers. |
| Accumulative Balance | Restricted internal balance used under documented purchase, transfer, fee, and redistribution rules. Its lifetime is temporarily 180 days while a timer-reset fix is prepared; see [Contract Parameters](/en/contract-parameters). |
| Protocol Reward Cap | Remaining reward eligibility for the active NFT cycle; on-chain term: *Income Limit*. |
| Token Reserve Balance | Designated liquidity-pool balance supporting DA mechanics. |
| Dev Balance | Protocol and operating allocations. |
| Price Impact Balance | Reserve used by documented price-impact functions. |

<Note>
  **FinPro balances are separate.** FinPro positions are opened directly from the user's EVM wallet in USDT (BEP-20) and paid out to the same wallet. They do not use the Regular Balance or the Accumulative Balance. See [FinPro & FinFlow](/en/finpro-finflow).
</Note>

## Payment Priority

<Steps>
  <Step title="Selected valid Voucher">
    If the user explicitly applies a valid voucher at checkout, its value is consumed first.
  </Step>
  <Step title="Accumulative Balance">
    Applied when eligible and selected, under the documented fee rules.
  </Step>
  <Step title="Regular Balance">
    Any remaining amount is deducted from the Regular Balance.
  </Step>
</Steps>

<Note>
  All transactions on [BNB Smart Chain](https://www.bnbchain.org/en/bnb-smart-chain) require standard network gas fees paid in **BNB**, separate from [USDT](https://tether.to/) balances used within the ecosystem. Contract deployments and balances are publicly verifiable on [BscScan](https://bscscan.com/); official contract addresses are listed at [app.rwanftfi.com/smart-contracts](https://app.rwanftfi.com/smart-contracts).
</Note>
