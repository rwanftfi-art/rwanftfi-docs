## Фасети Diamond

| Фасет | Функція |
|---|---|
| AdminFacet | Зміна гаманців і обмеження акаунтів, мінтинг спеціальних NFT та автоматизовані сервісні операції. |
| ParametersFacet | Параметри протоколу, налаштування NFT, типи Подарункових NFT, увімкнення та вимкнення функцій, періоди фармінгу та діапазони комісій. |
| MarketingFacet | Реєстрація, купівлі NFT і розрахунки партнерських винагород. |
| FarmingFacet | Майнінг NFTM і Фармінг DA. |
| PaymentFacet | Депозити, виведення, ваучери та перекази між балансами. |
| TreeFacet | Розміщення та глибина в партнерській мережі. |
| ResolverFacet | Прострочені значення, обробка ваучерів і врегулювання Frozen Balance. |
| ViewFacet | Запити лише для читання щодо користувачів, балансів і мережі. |

Diamond також містить стандартні фасети EIP-2535: DiamondCutFacet для оновлень, DiamondLoupeFacet для інтроспекції та OwnershipFacet.

## Контракти NFT

- Звичайні NFT використовують непарні token ID.
- Подарункові NFT використовують парні token ID.
- Ambassador NFT використовують окремий контракт і конфігурацію.

## Матриця оновлюваності

| Компонент | Модель |
|---|---|
| Контракт Diamond | Оновлюється через facet cuts. |
| TokenReserve / DA | Оновлюється через задокументований проксі-механізм. |
| Контракти NFT | Задокументовані як такі, що не оновлюються. |
| GovToken | Задокументований як такий, що не оновлюється, з фіксованою емісією. |
| AdminContract | Задокументований як такий, що не оновлюється. |

## Управління ролями

| Роль | Задокументовані повноваження |
|---|---|
| Контракт DAO | Застосовує зміни параметрів у межах он-чейн діапазонів, змінює налаштування NFT, вмикає та вимикає функції, встановлює періоди фармінгу та діапазони комісій, схвалює зміни гаманців, обмежує та відновлює акаунти. |
| `ADMIN_ROLE` | Надання та відкликання ролей; мінтинг Подарункових NFT і Ambassador NFT та керування типами Подарункових NFT; встановлення комісії за транзакцію в межах її діапазону. |
| `SERVICE_ROLE` | Виконання задокументованих автоматизованих і крос-чейн сервісних операцій. |
| `SIGNER_ROLE` | Перевірка авторизованих підписів для визначених дій. |
| `MINTER_ROLE` | Мінтинг токена або типу NFT, закріпленого за цією роллю. |
| Власник Diamond | Оновлення фасетів через `diamondCut` і передача права власності. |

Перелік функцій кожної ролі наведено в розділі про централізацію [звіту CertiK](/uk/security).

## Схема балансів

| Баланс | Призначення |
|---|---|
| Звичайний Баланс | Дозволені виведення, купівлі та ваучери. |
| Накопичувальний Баланс | Обмежений внутрішній баланс, що використовується за задокументованими правилами купівель, переказів, комісій і перерозподілу. Його строк дії тимчасово становить 180 днів, поки готується виправлення скидання таймера; див. [Параметри контракту](/uk/contract-parameters). |
| Ліміт винагород протоколу | Залишкове право на винагороди в активному циклі NFT; он-чейн термін: *Income Limit*. |
| Баланс Token Reserve | Баланс виділеного пулу ліквідності, що підтримує механіку DA. |
| Dev Balance | Протокольні та операційні алокації. |
| Price Impact Balance | Резерв, що використовується задокументованими функціями цінового впливу. |

<Note>
  **Баланси FinPro відокремлені.** Позиції FinPro відкриваються безпосередньо з EVM-гаманця користувача в USDT (BEP-20), і виплати надходять на той самий гаманець. Звичайний Баланс і Накопичувальний Баланс у них не використовуються. Див. [FinPro та FinFlow](/uk/finpro-finflow).
</Note>

## Пріоритет платежів

<Steps>
  <Step title="Обраний дійсний ваучер">
    Якщо користувач явно застосовує дійсний ваучер під час оплати, його вартість використовується першою.
  </Step>
  <Step title="Накопичувальний Баланс">
    Застосовується, якщо його дозволено й обрано, за задокументованими правилами комісій.
  </Step>
  <Step title="Звичайний Баланс">
    Будь-яка решта суми списується зі Звичайного Балансу.
  </Step>
</Steps>
