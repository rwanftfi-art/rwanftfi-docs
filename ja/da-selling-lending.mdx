## DA売却とバーンメカニクス

DAを売却する際、異なる条件を持つ2つの異なるシナリオがあります。

1. **手動売却(ユーザーが独自に売却):**
   * ユーザーは現在価格でDA価値の**75%**をUSDTで受け取ります。
   * 売却されたDAトークンの**100%**が恒久的にバーンされます。
   * 残りの25%はプロトコル手数料としてUSDT裏付けとしてプールに留まります — トークンが減り、流動性が同じになることで、この25%が直接価格成長を牽引します。

2. **オートセル(TokenStack期間満了後にトリガー):**
   * ユーザーはオートセル日の価格でDA価値の**70%**をUSDTで受け取ります。
   * オートセルされたDAトークンの**100%**が恒久的にバーンされます。
   * 残りの30%はプロトコル手数料としてUSDT裏付けとしてプールに留まります — この30%が価格を上昇させる原動力です。
   * ユーザーが期間満了前に手動売却していなかった場合、オートセルが自動的にトリガーされます。

両方のケースで売却されたトークンの100%がバーンされます — 25%/30%はUSDT裏付けとしてプールに留まるプロトコル手数料です。これが価格成長を牽引するメカニズムです:トークン減少 + 同じ流動性 = DA1単位あたりの価格上昇。オートセルは5%低い支払率となり、ユーザーがDAポジションを能動的に管理するインセンティブとなっています。

<Warning>
  **DA売却はNFTのインカムリミットを消費します。** DAの手動売却またはオートセルのたびに、USDT支払額に応じてNFTの残りインカムリミットが減少します — マーケティング報酬と同等の扱いです。インカムリミットが枯渇している場合、手動DA売却は不可能となり(システムが支払額をクレジットできない)、オートセルでは収益の100%がDA流動性プールまたはバーンへ振り向けられます(具体的なメカニズムはDAOの設定により決定)。DA売却時に支払を受け取るためには、オートバイまたは手動NFT更新によりインカムリミットをアクティブに保ってください。
</Warning>

<Info>
  TokenStack期間満了前に手動売却しなかった場合、**オートセル**が自動的にトリガーされます。5%少ない支払い(75%対70%)となり、能動的な管理を促します。
</Info>

## オートセル期間

DAはファーミング後、即座にユーザーに100%利用可能です — ロックアップ期間はありません。ユーザーはいつでも手動売却(75%をUSDTで受領)するか、DAを担保にローンを受けることができます。ユーザーが**何もしなかった**場合、システムは**残高**から段階的に4期間にわたり計**365日(1年)**かけて自動強制売却をトリガーします。期間の長さはオンチェーンで日数単位で記録されています(120 / 90 / 90 / 65日)。以下の月数表記は読みやすさのための近似値です。

**100 DAから始まる例:**

<Steps>
  <Step title="期間1 — 120日後(約4ヶ月)に25%オートセル">
    120日(約4ヶ月)以内に手動売却していない場合、現在のDA残高の25%がオートセルされます。100 DAの25% = **25 DAオートセル** → 現在価格で価値の70%をUSDTで受領 → 25 DAの100%がバーン → 残り:**75 DA**
  </Step>
  <Step title="期間2 — さらに90日後(約3ヶ月、210日目)に40%オートセル">
    残高の40%がオートセル。75 DAの40% = **30 DAオートセル** → 残り:**45 DA**
  </Step>
  <Step title="期間3 — さらに90日後(約3ヶ月、300日目)に50%オートセル">
    残高の50%がオートセル。45 DAの50% = **22.5 DAオートセル** → 残り:**22.5 DA**
  </Step>
  <Step title="期間4 — さらに65日後(約2ヶ月、365日目)に100%オートセル">
    残高の100%がオートセル。ポジションが完全にクローズ。22.5 DAの100% = **22.5 DAオートセル** → 残り:**0 DA**
  </Step>
</Steps>

<Note>
  上記のオートセル割合(25% / 40% / 50% / 100%)は現在のプロトコル設定を表しています。具体的な値はプロトコルパラメータとして格納されており、標準的なガバナンス手続きの対象です。最新の値は常にスマートコントラクトまたは現在のプロトコルドキュメントで確認してください。
</Note>

各オートセルは元のファーミング価格ではなく、その時点でのDA価格で実行されます。価格は時間とともに成長するため、後続のオートセルではより高い価格でトークンがバーンされ — デフレがさらに強化されます。

<Warning>
  **インカムリミットゼロでのオートセル:** DAオートセルがトリガーされ、ユーザーのNFTのインカムリミットがゼロ(NFTが更新されていない)の場合、収益の100%が流動性プールまたはDAバーンへ向けられます。具体的なメカニズムはDAOの設定により決定されます。オートセル支払を受け取るために、ユーザーは常にアクティブなインカムリミットを維持すべきです。
</Warning>

## レンディング(DA担保のクレジット)

プレミアムおよびエリートNFTホルダー(レベル5以上)は、売却の代わりにDA担保に対してUSDTローンを受けることができます。ローンは、1回の完了したマイニングおよびファーミングサイクルからの特定のDAバッチを担保とします — バッチの一部ではなく、バッチ全体を一度に。下位ティアはマイニングを実行せず、借入に使用できるDA担保がありません。

すべてのローンは固定**70% LTV**で発行され、発行時にDA流動性プールへ振り向けられる一回限りの**5%手数料**が徴収されます。返済時は何も徴収されません。借り手はレギュラーバランスにローン総額の95%を受け取ります。例:DA価格1.00 USDTで100 DAバッチの場合、総ローンは70 USDT、手数料は3.50 USDT、借り手の純支払額は66.50 USDTです。

決定的な構造的特性は、DA価格が発行時に`loan.price`として記録され、その後再計算されないことです。その後のDA価格上昇は債務を増加させません — 借り手は今日の価格でUSDT流動性を引き出しながら、将来の価格上昇のアップサイドを保持します。ローンには固定満期日がなく、バッチがオートセルサイクルに入る前であれば全額または部分的にいつでも返済でき、特定のバッチはその生涯にわたって一度しか担保に入れられません。

バッチがオートセルサイクルに入る前にローンが返済されなかった場合、担保化されたDAは標準の4期間スケジュールを通じて段階的にバーンされます。借り手は発行時に受け取ったUSDTを保持します;バーンされた各部分のUSDT価値がDA流動性プールへ流れます。オートセル期間の間、借り手はまだ`repay()`を呼び出してまだ担保化されているDAを回収することができます。

<Warning>
  **レンディングデフォルト - 段階的バーン:** バッチがオートセルサイクルに入る前にローンが返済されなかった場合、担保は標準の4期間スケジュール(120 / 90 / 90 / 65日、計365日にわたって**残存**担保化DAの25% / 40% / 50% / 100%をバーン)を通過します。バーンされたDAの100%が恒久的に破壊されます;`loan.price`での対応するUSDT価値がDA流動性プールへ振り向けられます。借り手はバーンされた部分に対してUSDTを受け取り**ません** — デフォルトしたバッチからの唯一の経済的回収は発行時に受け取ったUSDTです。

  **部分回収は常に可能です。** 借り手は任意の2回のオートセル期間の間に`repay()`を呼び出し、まだ担保化されているものに対してのみ支払うことで**残存**担保化DAを回収できます。以前の期間ですでにバーンされたDAは回収できませんが、次のバーンはその期間境界の前に返済することで止めることができます。
</Warning>

<Note>
  **`repay()`がオートセル開始後 - CertiK後の挙動修正(RWA-58):** 以前のコントラクトバージョンでは、バッチがオートセルサイクルを超えると`repay()`は取り消されていました。CertiK監査後、これが修正されました:`repay()`はローンの生涯のいずれの段階でも呼び出し可能となっています。バッチがすでにオートセルトリガーを超えている場合、コントラクトはまず`_processExpiredStacks()`を実行してすでに経過したすべての期間を清算 — これにより対応する担保の割り当てがバーンされます — その後バーン後の残りに対して処理が進みます。

  実際の結果:遅い`repay()`はすでにトリガーされたバーンを「先取り」できません。担保**全体**を保護するには、借り手は最初のオートセルトリガー(期間1、現在バッチ生成後120日目)を超える前に返済する必要があります。
</Note>
