RWANFTFIは[EIP-2535](https://eips.ethereum.org/EIPS/eip-2535)ダイヤモンドアーキテクチャを採用しており、7つの機能別ファセット、独立したNFTおよび準備金コントラクト、規定されたアップグレード可能性メカニズム、ロールベースの権限、複数の内部残高タイプを備えています。

## ダイヤモンドファセット

| ファセット | 機能 |
|---|---|
| AdminFacet | ロール、パラメータ、承認済み転送、特殊NFTの発行を管理します。 |
| MarketingFacet | 登録、NFT購入、パートナー報酬の計算を扱います。 |
| FarmingFacet | NFTMマイニングとDAファーミングを扱います。 |
| PaymentFacet | 入金、出金、バウチャー、残高間の移動を扱います。 |
| TreeFacet | パートナーネットワークの配置と深度を扱います。 |
| ResolverFacet | 期限切れ値の処理、バウチャー処理、Frozen Balanceの解決を扱います。 |
| ViewFacet | ユーザー、残高、ネットワークに関する読み取り専用クエリを扱います。 |

## NFTコントラクト

- 通常NFTは奇数のトークンIDを使用します。
- ギフトNFTは偶数のトークンIDを使用します。
- アンバサダーNFTは別個のコントラクトと設定を使用します。

## アップグレード可能性マトリックス

| コンポーネント | モデル |
|---|---|
| ダイヤモンドコントラクト | ファセットカットを通じてアップグレード可能です。 |
| TokenReserve / DA | 規定されたプロキシメカニズムを通じてアップグレード可能です。 |
| NFTコントラクト | アップグレード不可と規定されています。 |
| GovToken | 固定供給量でアップグレード不可と規定されています。 |
| AdminContract | アップグレード不可と規定されています。 |

## ロール管理

| ロール | 規定された権限 |
|---|---|
| `ADMIN_ROLE` | ロールの付与・剥奪、および許可されたプロトコルパラメータの変更。 |
| `SERVICE_ROLE` | 規定された自動化処理およびクロスチェーンサービス操作の実行。 |
| `SIGNER_ROLE` | 特定のアクションに対する承認済み署名の検証。 |
| `MINTER_ROLE` | そのロールに割り当てられたトークンまたはNFTタイプの発行。 |

## 残高スキーマ

| 残高 | 用途 |
|---|---|
| 通常バランス | 対象となる出金、購入、バウチャーに使用されます。 |
| アキュムレーティブバランス | 規定された購入・転送・手数料・再分配ルールの下で使用される、制限付きの内部残高です。 |
| プロトコル報酬上限 | 現在のNFTサイクルにおける残りの報酬資格額です。オンチェーン用語:*Income Limit*。 |
| トークン準備バランス | DAメカニクスを支える、指定された流動性プール残高です。 |
| 開発者バランス | プロトコルおよび運営のための配分です。 |
| 価格影響バランス | 規定された価格影響機能で使用される準備金です。 |

## 支払い優先順位

<Steps>
  <Step title="有効なバウチャーの選択">
    ユーザーがチェックアウト時に明示的に有効なバウチャーを適用した場合、その価値がまず消費されます。
  </Step>
  <Step title="アキュムレーティブバランス">
    対象であり、かつ選択された場合、規定された手数料ルールの下で適用されます。
  </Step>
  <Step title="通常バランス">
    残額は通常バランスから差し引かれます。
  </Step>
</Steps>

<Note>
  [BNB Smart Chain](https://www.bnbchain.org/en/bnb-smart-chain)上のすべての取引には、**BNB**で支払う標準的なネットワークガス手数料が必要です。これはエコシステム内で使用される[USDT](https://tether.to/)残高とは別のものです。コントラクトのデプロイと残高は[BscScan](https://bscscan.com/)上で公開検証可能です。
</Note>
